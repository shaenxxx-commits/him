# docs/METHOD.md

Метод исследования HIM.

## 1. Область применения

Расследование ведётся по публичным следам и доступным документам. Полевой цикл применяется к каждому эпизоду.

## 2. Базовый принцип

Сначала поле, потом модель. Реальность не втискивается в заранее заданную гипотезу.
Наблюдение, действие, результат и интерпретация остаются различимыми.

## 3. Полевой цикл

    FIELD
    ↓
    OBSERVE
    ↓
    MAP
    ↓
    HYPOTHESIS
    ↓
    ACT
    ↓
    RESULT
    ↓
    ASSESS
    ↓
    LEARN
    ↓
    NEXT MOVE

Каждый цикл оставляет проверяемый след.

## 4. Два контура

### Исследовательский
Field → observation → data → hypothesis → test → knowledge.

### Публикационный
Field → material → verification → publication.

Контуры могут взаимодействовать, но не смешиваются (I18).
Публикация — по санкции Архитектора, не автоматический продукт.

## 5. Состояния знания

Двумерная модель — `docs/KNOWLEDGE_STATES.md`.
Кратко: [ФАКТ], [ПОДТВЕРЖДЕНО], [ГИПОТЕЗА], [НЕИЗВЕСТНО], [МОЯ ПОЗИЦИЯ], [ВНЕШНИЙ — <имя>].
Переходы — `meta/transitions.md`.

## 6. Минимальная полевая запись

См. `records/README.md`. Обязательные поля:
FIELD / DATE / OBSERVER / OBSERVATION / SOURCE / ACTION / RESULT / INTERPRETATION / HYPOTHESIS / UNKNOWN / NEXT STEP.

## 7. Run Structure

Каждый завершённый прогон производит:
1. Run record (`records/NNN-slug.md`).
2. Сохранённые raw внешних (или явный `UNKNOWN` / `archived-external`).
3. Lead synthesis — отдельный документ (`records/NNN-LEAD-SYNTHESIS-runN.md`).
4. Явное решение, если принято (`DECISIONS.md`).
5. Явное следующее наблюдение / действие.
6. Коммит.
7. Push в origin/main (если origin есть).

Следующий прогон не начинается, пока предыдущий не задокументирован и не запушен.

### Setup-ран

Ран без полевого цикла (создание репо, ядро, библиотека) оформляется как LEAD SYNTHESIS: что сделано, что обнаружено, что решено. Полевых OBS/ACT не создаётся.

## 8. ACT-whitelist

Разрешено:
- открывать публичные страницы;
- сохранять выдержки и метаданные;
- проверять публичные реестры (ЕГРПОУ, YouControl, OpenCorporates, судовые реестры);
- сопоставлять два источника;
- смотреть архивные копии (Wayback и аналоги);
- повторять поиск по заранее определённому запросу;
- проверять технические артефакты (WHOIS, DNS, CT-логи, публичные API).

Запрещено (I2):
- взлом, обход авторизации, оплата закрытого доступа;
- активные действия против фигурантов;
- скрытый сбор персональных данных;
- контакты с фигурантами от имени проекта.

Расширение whitelist — только по санкции Архитектора.

## 9. Классы источников

- **Официальные сообщения** — НАБУ, САП, суды, правоохранительные органы.
- **Судебные документы** — решения, постановления, материалы производств (ЄДРСР).
- **Первичные документы** — сканы, PDF, официальные бумаги, договоры (если опубликованы).
- **Публичные реестры** — ЕГРПОУ, YouControl, OpenCorporates, судовые реестры.
- **Журналистика** — публикации СМИ и расследования (с атрибуцией).
- **Интервью и заявления** — с атрибуцией и контекстом.
- **Соцсети и публичные архивы** — профили, посты, Wayback.
- **Технические источники** — WHOIS, DNS, CT-логи, публичные API.

Приоритет: первоисточники выше перепечаток (I7).

## 10. Разделение «факт публикации ≠ истинность»

Утверждение «источник опубликовал X» — наблюдаемый факт.
Утверждение «X истинно» — требует отдельной проверки (I5).

## 11. Провенанс (слои)

Слои различимы:
- `raw-external` — захвачено в момент прогона.
- `archived-external` — повторно выданное источником из persistent-чата на указанную дату.
- `RUN RECORD`
- `LEAD SYNTHESIS`
- `DECISION`
- `NEXT OBSERVATION`

Raw не редактируется молча. Ошибки, загрязнения, противоречия сохраняются и классифицируются в синтезе.

### Крупные raw (> ~20 КБ)

Raw вне git (`~/raw-external/him/`). В записи: путь, размер, sha256, дата, наблюдатель, источник.

### Восстановление утраченного сырья

Допустимо: повторный запрос к источнику → `archived-external` (узел, чат, MS, дата).
Недопустимо: реконструкция по памяти (I3). Если дословный ответ не сохранён — `UNKNOWN`.

## 12. Git Rule

После каждого завершённого прогона:
1. Сохранить raw.
2. Заполнить run record.
3. Заполнить Lead synthesis.
4. Зафиксировать решение и следующее наблюдение.
5. Commit.
6. Push.
7. Проверить локальный HEAD, удалённый HEAD, чистое дерево.

Git — внешняя память проекта.

## 13. Память экспедиции

    WHAT WAS SEEN
    ↓
    WHAT WAS THOUGHT
    ↓
    WHAT WAS DONE
    ↓
    WHAT HAPPENED
    ↓
    WHAT CHANGED
    ↓
    WHAT REMAINS UNKNOWN

## 14. Ограничения и объём фиксации

- Только публичные следы (I2).
- Фиксация — минимально достаточная (I17). Не создавать документы «про запас».
- Шум (промежуточные рассуждения, повторы) — не фиксируется. Фиксируется результат:
  наблюдение, статус, источник, следующее действие.
- Полный протокол — в INVARIANTS (I3, I19) и meta/transitions.
