# INVARIANTS.md

Инварианты HIM. Нарушение — отказ протокола проекта, не стилистический дефект.
При конфликте с другими документами — приоритет за INVARIANTS.md.
Изменение инвариантов — только через accepted-решение в DECISIONS.md.

## I1 — Предмет и границы
Расследование ведётся в рамках предмета, зафиксированного в `docs/VISION.md`.
Расширение границ — только через accepted-решение.

## I2 — Источники
Используются публично доступные материалы сети. Работа в серых зонах допустимого:
без взлома, обхода авторизации, оплаты доступа, активных действий против фигурантов.
Публичное — рабочее.

## I3 — Статусы знания
Каждое утверждение имеет явный статус: `[ФАКТ]`, `[ПОДТВЕРЖДЕНО]`, `[ГИПОТЕЗА]`,
`[НЕИЗВЕСТНО]`, `[МОЯ ПОЗИЦИЯ]`, `[ВНЕШНИЙ — <имя>]`.
Повышение статуса — только при наличии источника и фиксации перехода (`meta/transitions.md`).
`[ФАКТ]` — только для VERIFIED. Реконструкция утраченного сырья по памяти запрещена.

## I4 — Провенанс
Провенанс сохраняется явно. Различение: внешний факт ≠ представление ≠ наблюдение ≠
интерпретация ≠ результат. Утверждение без прослеживаемого источника не используется
как факт.

## I5 — Факт публикации ≠ истинность
Утверждение «источник опубликовал X» и «X истинно» — разные утверждения.
Публикация подтверждает факт публикации, не истинность содержания.

## I6 — Связи с основанием
Связь между фигурантами фиксируется только с типом основания:
документально установлена / прямое заявление источника / косвенное свидетельство /
аналитически предполагаемая / неподтверждённая гипотеза.
Упоминание двух лиц в одном документе не является связью.

## I7 — Первоисточники приоритетны
Судебные решения, материалы следствия, официальные сообщения, первичные документы —
выше журналистских публикаций. Перепечатка одного материала не является независимым
подтверждением.

## I8 — Гипотезы
У каждой гипотезы фиксируются: основание, подтверждающие, противоречащие,
альтернативные объяснения, неизвестные обстоятельства, условия пересмотра/закрытия.
Гипотеза не становится фактом без перехода статуса.

## I9 — Решения фиксируются
Любое значимое решение — в `DECISIONS.md` (статус, дата, утверждающий, контекст,
решение, основание, последствия, условие пересмотра).
Устное решение без записи не является решением проекта.

## I10 — Существенные решения утверждает Архитектор
Ведущий не подменяет решение Архитектора своими предположениями.
Действия (создание, изменение, удаление, push, изменение инвариантов) — только по
явной команде. Обсуждение идеи не является командой.

## I11 — Одна команда → вывод → следующая
Не стекать команды. Не утверждать, что файл прочитан или команда выполнена, если это
не подтверждено выводом в текущей сессии. Свежий терминальный вывод — источник истины
о состоянии репозитория; web-интерфейс GitHub — не источник.

## I12 — Ничего не удаляется без следа
Устаревшее переносится в `ARCHIVE/` с датой и причиной. Запрет действует и для
документов, и для записей `records/`. Исключение — временные и тестовые файлы,
явно помеченные как таковые до коммита.

## I13 — Правка документов
Правка изменяемых документов (`INVARIANTS.md`, `CURRENT_STATE.md`, `README.md`,
`docs/*.md`, `meta/agent-rules.md`, `meta/handoff-protocol.md`,
`meta/handoff-current.md`) — полным документом одним блоком.
Для append-only журналов (`DECISIONS.md`, `PROVENANCE.md`, `meta/transitions.md`,
`meta/open-questions.md`, `records/`) — фрагментом в конец.

## I14 — Дата
Дата для записей — из терминального `date` в текущей сессии. Выводить дату из
контекста, памяти или предыдущих сообщений запрещено. Если дата не зафиксирована —
явная пометка `[ДАТА НЕ ЗАФИКСИРОВАНА]`.

## I15 — Fallback при отсутствии Архитектора
Если обнаружено состояние, требующее решения, а Архитектор недоступен — не продолжать
зависимые действия, зафиксировать состояние в `CURRENT_STATE.md` (раздел «Заблокировано»),
пометить неопределённое как `[НЕИЗВЕСТНО]`, остановиться. Не разрешать конфликт
самостоятельно.

## I16 — Провенанс правок через git
Каждый коммит: `[<роль> / <модель>] <документ>: что изменено; основание`.
Формат даёт провенанс через `git blame`.

## I17 — Минимализм инфраструктуры
Не создавать инфраструктуру, API, автоматизации или большой комплект документов без
отдельного согласования. Лучше 4 работающих документа, чем 15 пустых заготовок.
Расширение — только по реальной потребности и отдельному решению.

## I18 — Разделение контуров
Исследовательский контур (наблюдение → данные → гипотеза → проверка → знание) и
публикационный контур (материал → проверка → публикация) разделены.
Публикация — по санкции Архитектора, не автоматический продукт расследования.

## I19 — Внешние наблюдатели
Внешние (GPT, Grok, Sakana, Kimi K2) — независимые контуры. Их выход не является
фактом. Атрибуция обязательна. Разногласия не сглаживаются. Kimi K2 — отдельный
режим (аудит/развилка), не смешивается с прогонами.
