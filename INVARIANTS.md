# INVARIANTS.md

Инварианты HIM. Нарушение — отказ протокола, не стилистический дефект.
При конфликте с другими документами — приоритет за INVARIANTS.md.
Изменение — только через accepted-решение в DECISIONS.md.

## I1 — Предмет и границы
Расследование в рамках `docs/VISION.md`. Расширение — только accepted-решение.

## I2 — Источники
Публично доступные материалы. Серые зоны допустимого: без взлома, обхода авторизации,
оплаты доступа, активных действий против фигурантов. Публичное — рабочее.

## I3 — Статусы знания
Каждое утверждение маркируется:
- `[ФАКТ]` — VERIFIED, первичный документ (указ, постановление, решение суда) назван.
- `[ПОДТВЕРЖДЕНО]` — SUPPORTED: официальное сообщение без первичного документа,
  либо множественные независимые неофициальные источники.
- `[ГИПОТЕЗА]` — один неофициальный источник, заявление фигуранта, предположение.
- `[ОПРОВЕРГНУТО]` — данные противоречат ранее выдвинутой версии. Не равно UNKNOWN.
- `[НЕИЗВЕСТНО]` — данных нет.
- `[МОЯ ПОЗИЦИЯ]` — позиция агента, не факт.
- `[ВНЕШНИЙ — <имя>]` — вывод внешнего наблюдателя.

Официальная фиксация — один фактор достоверности, не критерий.
Правоохранительная система — часть предмета, не арбитр.
Тип утверждения (OBSERVATION / RESULT / INTERPRETATION) — независимое измерение от статуса.
Повышение статуса — только при источнике и фиксации перехода (`meta/transitions.md`).
Реконструкция утраченного сырья по памяти запрещена.

## I4 — Провенанс
Внешний факт ≠ представление ≠ наблюдение ≠ интерпретация ≠ результат.
Утверждение без прослеживаемого источника не используется как факт.

## I5 — Факт публикации ≠ истинность
Публикация подтверждает факт публикации, не истинность содержания.
Факт документа ≠ факт содержания документа.

## I6 — Связи с основанием
Связь фиксируется только с типом: документально установлена / прямое заявление
источника / косвенное свидетельство / аналитически предполагаемая / неподтверждённая
гипотеза. Упоминание двух лиц в одном документе — не связь.

## I7 — Первоисточники приоритетны
Судебные решения, материалы следствия, официальные сообщения, первичные документы —
выше журналистики. Перепечатка ≠ независимое подтверждение.

## I8 — Гипотезы
У каждой: основание, подтверждающие, противоречащие, альтернативы, неизвестные
обстоятельства, условия пересмотра/закрытия. Гипотеза не становится фактом без
перехода статуса.

## I9 — Решения фиксируются
Значимое решение — в `DECISIONS.md` (статус, дата, утверждающий, контекст, решение,
основание, последствия, условие пересмотра). Устное решение без записи — не решение.

## I10 — Существенные решения утверждает Архитектор
Ведущий не подменяет решение Архитектора. Действия (создание, изменение, удаление,
push, изменение инвариантов) — только по явной команде. Обсуждение ≠ команда.

## I11 — Одна команда → вывод → следующая
Не стекать. Не утверждать о прочтении/выполнении без подтверждения выводом в текущей
сессии. Свежий терминал — источник истины о состоянии репозитория; web GitHub — не источник.

## I12 — Ничего не удаляется без следа
Устаревшее — в `ARCHIVE/` с датой и причиной. Исключение — временные файлы, помеченные
до коммита.

## I13 — Правка документов
Изменяемые — полным документом одним блоком. Append-only (`DECISIONS.md`,
`meta/transitions.md`, `records/`) — фрагментом в конец.

## I14 — Дата
Только из терминального `date` в текущей сессии. Иначе — `[ДАТА НЕ ЗАФИКСИРОВАНА]`.

## I15 — Fallback без Архитектора
Не продолжать зависимые действия. Зафиксировать в `CURRENT_STATE.md` раздел
«Заблокировано», пометить `[НЕИЗВЕСТНО]`, остановиться. Конфликт самостоятельно не
разрешать.

## I16 — Провенанс правок через git
Коммит: `[<роль> / <модель>] <документ>: что; основание`.

## I17 — Минимализм
Не создавать инфраструктуру и документы без реальной потребности. Лучше 4 работающих
документа, чем 15 пустых. Расширение — по триггеру и решению.

## I18 — Контуры
Исследовательский и публикационный разделены. Публикация — по санкции Архитектора.

## I19 — Внешние наблюдатели
GPT, Grok, Sakana, Kimi K2 — независимые контуры. Выход не факт, атрибуция обязательна,
разногласия не сглаживаются. Kimi K2 — отдельный режим (аудит/развилка).
Внешний, ссылающийся на содержимое репозитория, обязан цитировать фрагмент с путём.
Ссылка «я читал repo X» — не доказательство; проверка — терминалом.
Прогонные — clean init, независимая фаза, без выводов других моделей.
Состав прогона определяет Ведущий (минимум один, максимум три).
Внешние raw сохраняются: при первооткрытии, конфликте, ссылке на источник, новом методе.

## I20 — Правила работы агента

- MS N — первой строкой, сквозная в чате.
- Один шаг за раз. Коротко, без воды.
- Действия — только по явной команде.
- Не задавать вопросов, ответ на который есть в документе или контексте.
- Ошибка в предыдущем ответе — признать, откатить.
- Anti-patterns: выдумывание состояния; утверждение о прочтении/выполнении без факта;
  старый handoff как текущий; свой анализ как вывод внешнего; приписывание наблюдателю
  придуманного; молчаливое разрешение конфликта; старт зависимой операции без проверки;
  реконструкция по памяти; самовольные правки; правка своего изменения без проверки;
  heredoc с фенсед-блоками; обход закрытого реестра вместо UNKNOWN; продолжение без
  Архитектора без фиксации в «Заблокировано»; самостоятельное разрешение конфликта.

## I21 — Передача контекста

При смене ведущего: свежий терминал (HEAD, status, ls-remote) → ключевые файлы →
пробелы `[НЕИЗВЕСТНО]` → полномочия → только затем действия.
Handoff не заменяет первоисточники. Web GitHub — не источник.
