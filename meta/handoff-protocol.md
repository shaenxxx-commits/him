# meta/handoff-protocol.md

Протокол передачи контекста между сессиями и агентами.
Применяется с `meta/handoff-current.md` и `meta/agent-rules.md`.

## 1. Назначение

Handoff — транспорт и набор обязательных проверок, не замена первоисточникам.

## 2. Иерархия источников истины

1. Текущий ввод Архитектора.
2. Свежий терминальный вывод в текущей сессии.
3. Содержимое репозитория по конкретному SHA.
4. Документация проекта (INVARIANTS, CURRENT_STATE, DECISIONS, meta).
5. Handoff / сводки предыдущих чатов.
6. Память агента / реконструкция.

Уровень 6 не используется для фактов. При конфликте — выше.

Web-интерфейс GitHub — не источник. Доказательство: `git ls-remote origin refs/heads/main` + локальный HEAD + `git status --short`.

## 3. Свежесть

«Свежий» — полученный в текущей сессии. Handoff не устанавливает текущее состояние.

## 4. Конфликт источников

1. Зафиксировать конфликт.
2. Назвать источники.
3. Предпочесть свежий авторитетный.
4. Остаток — `[НЕИЗВЕСТНО]` до разрешения.

## 5. Маркировка утверждений

- `[ФАКТ]` — VERIFIED, источник назван.
- `[ПОДТВЕРЖДЕНО]` — SUPPORTED.
- `[ГИПОТЕЗА]` — предположение.
- `[НЕИЗВЕСТНО]` — данных нет.
- `[МОЯ ПОЗИЦИЯ]` — позиция агента, не факт.
- `[ВНЕШНИЙ — <имя>]` — дословный вывод внешнего.

`[МОЯ ПОЗИЦИЯ]` не маскирует внешнее мнение.

## 6. Процедура старта нового ведущего

Шаг 1 — Верификация идентичности handoff (проект, репо, HEAD, задача).
Шаг 2 — Свежее состояние (`git log`, `git status`, `git ls-remote`, ключевые файлы).
Шаг 3 — Зафиксировать пробелы (`[НЕИЗВЕСТНО]`, не заполнять).
Шаг 4 — Установить полномочия (роль, разрешено/запрещено, утверждающий).
Шаг 5 — Только после этого действовать.

## 7. Шаблон handoff

    HANDOFF PROTOCOL: <version>
    PROJECT: HIM
    REPOSITORY: https://github.com/shaenxxx-commits/him
    CURRENT HEAD: <verified SHA / [НЕИЗВЕСТНО]>
    ACTIVE TASK: <task / [НЕИЗВЕСТНО]>
    STATUS: <status>
    LAST OPERATOR DECISION: <decision / [НЕИЗВЕСТНО]>
    MANDATORY FILES: <list>
    UNVERIFIED: <list>
    OPEN QUESTIONS: <list>
    LAST MS: <n>

## 8. Восстановление утраченного сырья

Повторный запрос → `archived-external` (узел, чат, MS, дата). Реконструкция по памяти запрещена (I3). Если дословного нет — `UNKNOWN`.

## 9. Anti-patterns

- выдумывание состояния;
- утверждение о прочтении без факта;
- старый handoff как текущий;
- свой анализ как вывод внешнего;
- молчаливое разрешение конфликта;
- старт зависимой операции без проверки;
- реконструкция по памяти;
- web GitHub как источник.

## 10. Failure cases

- «я менял корректно» без источника;
- ссылка на внешнего, которого не было;
- правка, захватившая чужие заголовки;
- «делай как раньше» без конкретики;
- зеркала разошлись — назвать актуальное;
- документ без адресата — спросить, кому;
- web-страница GitHub как источник.
