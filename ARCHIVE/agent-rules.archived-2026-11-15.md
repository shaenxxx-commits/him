# meta/agent-rules.md

Правила работы LLM-агента в HIM. Применяется наравне с `INVARIANTS.md`.
При конфликте — приоритет за `INVARIANTS.md`.

## 1. Нумерация ответов

- Формат: `MS N` — отдельной первой строкой, ничем не предваряется.
- Один номер на один ответ. Не нумеровать шаги внутри одного ответа.
- Внутри блоков кода номер не ставится.
- Нумерация сквозная в чате, начинается с 1.

## 2. Формат ответов

- Коротко, без воды.
- Один шаг за раз. Одна команда → вывод → следующая. Не стекать.
- Промпты и команды — copy-paste одним блоком.
- Не повторять известное.
- Язык — язык запроса.
- В длинных сессиях — экономить контекст.

## 3. Режимы взаимодействия

- «Обсудим» / «набросай идею» — режим обсуждения. Без промптов, команд, блоков.
- Действия — только по явной команде.
- Обсуждение идеи не является командой.
- «Один шаг за раз» — не давать следующий шаг до вывода предыдущего.
- Самовольные действия (создание, удаление, правка) — нарушение протокола.

### Fallback при отсутствии Архитектора

Если требуется решение, а Архитектор недоступен:
1. Не продолжать зависимые действия.
2. Зафиксировать в `CURRENT_STATE.md` раздел «Заблокировано»: что обнаружено, почему требует решения, дата, условия разблокировки.
3. Пометить неопределённое как `[НЕИЗВЕСТНО]`.
4. Остановиться. Не разрешать конфликт самостоятельно.

## 4. Варианты и рекомендации

- Не давать варианты без рекомендации.
- Помечать выбор: [ПРЕДПОЧТИТЕЛЬНО].

## 5. Работа с фактами

- Прямо и честно, включая ограничения.
- Не додумывать. Спрашивать или `[НЕИЗВЕСТНО]`.
- Явная атрибуция внешних.
- Ошибка в предыдущем ответе — признать, откатить, не защищать.
- Не задавать вопросов, ответ на которые есть в документе или контексте.

## 6. Работа с терминалом

- Команды — готовы к вставке одним блоком.
- Результат — в чат.
- Указывать явно расположение файлов.
- Перед командой уточнять `pwd`, если значимо.
- После push — дождаться `git log -1 --oneline`, `git status --short`, `git ls-remote origin refs/heads/main`. Без подтверждения push не считается успешным.

### Формат коммита

    [<роль> / <модель>] <документ>: что изменено; основание

Роли: Архитектор, Ведущий, Архиватор, Kimi K2, прогонный, агент.
Модель: DeepSeek, GPT, Grok, Sakana, Kimi, человек.

### Длинные файлы и heredoc

Heredoc ненадёжен для содержимого с фенсед-блоками, вложенными heredoc, подстановками shell.
Признаки: зависание, обрезка, мусор.
Правила: разбивать на блоки; для фенсед-блоков — редактор; после записи — `wc -l` + `tail -5`.

## 7. Даты

- Дата — только из терминального `date`.
- Не выводить из контекста, памяти, документов.
- Если дата не получена — пометка `[ДАТА НЕ ЗАФИКСИРОВАНА]`.
- Для роли без терминала — дата из отчёта оператора.

## 8. Формат правки документов

- Изменяемые документы — полным документом одним блоком.
- Append-only журналы (`DECISIONS.md`, `PROVENANCE.md`, `meta/transitions.md`, `meta/open-questions.md`, `records/`) — фрагментом в конец.
- Правки — только по явной санкции на каждую правку.
- Новые файлы — запись командой + `wc -l` / `tail`.
- Raw > ~20 КБ — вне git + мета-запись (sha256).

## 9. Зачистка мусора

Временные, тестовые файлы — удалить или явно пометить на удаление до отчёта.

## 10. Внешние наблюдатели

- Внешние (GPT, Grok, Sakana, Kimi K2) — штатный узел.
- Атрибуция: [ВНЕШНИЙ — <имя>].
- Компиляция — извлекать полезное, не усреднять. Подлинные конфликты — как есть.
- Дословный текст наблюдателя не восстанавливать по памяти.
- Не печатать личные данные оператора.

### Kimi K2 — особый режим

Persistent context, доступ к public-репо, сложные задачи и концептуальные развилки.
Не смешивать с прогонами. Ресурс дорогой — бережно.

### Прогонные (GPT, Grok, Sakana)

Clean init: без контекста проекта, без выводов других моделей.
Состав прогона определяет Ведущий: минимум один, максимум три.
Независимая фаза — модели не видят друг друга. Interaction — только по прямому указанию, с фиксацией порядка.

### Синтез N внешних выходов

- Каждый ответ сохраняется отдельно.
- Совпадения — SUPPORTED.
- Расхождения — как есть.
- Противоречия — в `DECISIONS.md` или `meta/open-questions.md`.
- Синтез — отдельным документом (LEAD SYNTHESIS) со ссылками на raw.
- Мнение большинства не заменяет проверку по первоисточникам.

### Исполнитель и проверяющий

- Агент, вносящий изменение, не проверяет его сам.
- Ревью — другая модель или другой чат.
- Нормативные правки — ревью до коммита.
- Без проверяющего статус правки — proposed.

## 11. Anti-patterns

- выдумывание состояния проекта;
- утверждение о прочтении, которого не было;
- утверждение о выполнении, которого не было;
- обращение со старым handoff как с текущим;
- выдача своего анализа за вывод внешнего;
- приписывание наблюдателю придуманного;
- молчаливое разрешение конфликта источников;
- молчаливое изменение смысла решения;
- старт зависимой операции при непроверенном состоянии;
- «делай как раньше» без операции;
- реконструкция утраченного сырья по памяти;
- самовольные действия без команды;
- правка своего изменения тем же агентом без внешней проверки;
- heredoc с фенсед-блоками;
- обход закрытого реестра вместо `UNKNOWN`;
- продолжение при отсутствии Архитектора без фиксации в «Заблокировано»;
- самостоятельное разрешение конфликта вместо остановки.

## 12. Передача контекста

Через `meta/handoff-current.md` по формату `meta/handoff-protocol.md`.
Новый агент не принимает handoff на веру.
